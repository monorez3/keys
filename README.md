# Ключи

Маленькие умные функции. Каждый ключ — одна папка. Из неё сами собой получаются
три вещи, ни одну из которых не пишут руками:

- **HTTP-эндпоинт** — `GET /k/alive?link=@durov`, зовётся из любого кода;
- **инструмент MCP** — один адрес в настройках, и все ключи появляются внутри
  ассистента (Claude, Cursor, IDE) как обычные команды;
- **страница документации** — генерируется из манифеста.

## Запуск

```
pip install -r requirements.txt
python run.py            # http://127.0.0.1:8110
pytest tests/ -q
```

## Ключ доступа и клиент — как у ИИ-сервисов

```bash
curl -X POST https://АДРЕС/token          # -> kx_...
pip install monokeys                      # или одним файлом, см. ниже
```

```
# .env
KEYS_API_KEY=kx_...
```

```python
from monokeys import Keys

k = Keys()                    # ключ берётся из KEYS_API_KEY
res = k.alive("@durov")

print(res.is_alive)           # True
print(res.title)              # Pavel Durov

# нужен только счётчик — только он и придёт, уже числом
print(k.alive.members_count("@durov"))   # 11005185
print(k.alive.kind("ru_python"))         # group
print(k.alive.online_count("ru_python")) # 1730
print(k.alive.fields())                  # что этот ключ вообще умеет вернуть
```

То же самое без клиента — параметром `only`:

```
https://АДРЕС/alive/durov?only=members_count   ->  11005185
```

Имя поля сверяется с манифестом: опечатка вернёт список существующих полей,
а не пустоту, которую легко принять за ноль.

Методы клиента не зашиты в код: их список приходит с сервера, поэтому новый
ключ доступен сразу, без обновления клиента. Обращение к несуществующему ключу
падает понятной ошибкой со списком существующих.

Ключ доступа бесплатный и без регистрации — он нужен не ради денег, а чтобы
квота считалась на человека, а не на весь офис за одним IP. Без него всё тоже
работает, просто лимит ниже: 100 запросов в сутки против 2000.

Если ключ куда-то утёк — отозвать можно самому, отзыв действует сразу:

```bash
curl -X POST -H "Authorization: Bearer kx_..." https://АДРЕС/token/revoke
```

### Что защищает ключ

| От чего | Как |
| --- | --- |
| Подделка адреса заголовком | `X-Real-IP` читается только от прокси из `KEYS_TRUSTED_PROXIES`; по умолчанию не доверяем никому |
| Утечка ключа в логи | `token=` вырезается из строки запроса перед записью |
| Утечка базы | хранится sha256, самого ключа в базе нет |
| Кража ключа | самостоятельный отзыв, действует сразу и не воскресает из кэша |
| Тихая подмена | неизвестный или отозванный ключ — честный 401, а не молчаливое понижение до анонима |
| Штамповка ключей | 5 в сутки на адрес плюс общий суточный потолок против ботнета |
| Забивание очереди | ожидание общего крана ограничено: занято — честный 503, а не висящее соединение |
| Подслушивание | `KEYS_REQUIRE_HTTPS=1` — ключ, пришедший не по HTTPS, не принимается |

### Переменные окружения на проде

```
KEYS_TRUSTED_PROXIES=127.0.0.1   # адрес nginx; без этого заголовкам не верим
KEYS_REQUIRE_HTTPS=1             # ключ только по HTTPS
```

## Что такое ключ без всякого клиента

Ключ — это строка. Имя ключа, слэш, то что проверяем:

```
https://АДРЕС/alive/@durov
```

В ответ приходит готовая человеческая строка, не JSON:

```
жив · channel · Pavel Durov · 11 005 185 подписчиков
```

Ни сборки параметров, ни разбора ответа. Поэтому код на стороне человека
сводится к одной строке на любом языке:

```php
echo file_get_contents("https://АДРЕС/alive/@durov");
```

```python
print(urllib.request.urlopen("https://АДРЕС/alive/@durov").read().decode())
```

Дописать в конец `?fmt=bool` — придёт голое `true`/`false`. Дописать
`?fmt=json` — придёт полный ответ со всеми полями, если он зачем-то нужен.

На странице каждого ключа лежит сам ключ, форма «попробовать прямо тут» и
такие же готовые куски под **curl, Python, JavaScript, C++ (libcurl), Go и
PHP** — с настоящим адресом и настоящим значением, копируются как есть.
Генерируются из манифеста, поэтому не устаревают.

## Где посмотреть, что делает ключ

| Адрес | Для кого |
| --- | --- |
| `/<ключ>/<строка>` | сам вызов: ответ строкой (`?fmt=json` — полями, `?fmt=bool` — да/нет) |
| `/` | каталог: список ключей с описаниями |
| `/k/<id>/docs` | страница ключа: вход, ответ, примеры на 6 языках |
| `/llms.txt` | **вся** документация одним простым текстом — скормить ассистенту целиком |
| `/openapi.json` | машинная спека: генератор соберёт по ней клиент под ваш язык |
| `/keys` | короткий список в JSON |
| `/mcp` | все ключи как инструменты внутри ассистента |

Ни одна из этих страниц не пишется руками — все собираются из манифестов.

## Как добавить ключ

Положить папку в `keys/`. Больше нигде ничего регистрировать не нужно — реестр
находит ключ сам по наличию `key.json`.

```
keys/
  мой-ключ/
    key.json      # что делает, что принимает, что возвращает, сколько кэшировать
    handler.py    # async def run(params: dict, ctx) -> dict
```

`ctx` — единственная дверь наружу: `await ctx.fetch(url)` уже проходит через
общий кран запросов и не даст ключу расстрелять наш IP.

Правила, которые проверяет загрузчик (кривой ключ до каталога не доедет):
`id` совпадает с именем папки, у каждого параметра есть тип из списка,
есть `summary` — короткая строка, которую читает и человек, и ассистент.

## Сколько выдержит сервер

Замеры на боевой машине (2 ядра, 3.8 ГБ, OVH Франция, 12 контейнеров уже
крутятся, load average 0.21):

| Что мерили | Результат |
| --- | --- |
| Одна страница t.me | ~10 КБ, **75 мс** |
| Восемь параллельно | **171 мс** на всю пачку (~47 проверок/сек) |
| Разбор страницы | **0.085 мс** → ~11 700 страниц/сек на одном ядре |

Вывод: процессор и память не при чём — разбор в 900 раз дешевле сетевого
похода. Узкое место одно — **терпение t.me к нашему IP**, а его в цифрах никто
не публикует. Поэтому наружу ходим через общий кран на **5 запросов/сек**
(в 9 раз ниже того, что тянет железо) = **432 000 проверок в сутки**.

Кэш этот бюджет умножает: живой канал держим 6 часов, мёртвый — 1 час, потому
что мёртвый может воскреснуть, а живой вряд ли исчезнет. При типичном для
каталогов перекрытии запросов (70% попаданий) сутки дают около **1,4 млн**
ответов.

Отсюда потолок по людям:

| Кто | Проверок в сутки | Сколько таких поместится |
| --- | --- | --- |
| Выжимает квоту досуха | 2000 | **~200** |
| Собирает каталог | ~300 | ~1400 |
| Обычный через ассистента | ~30 | **~14 000** |

Ограничивать надо не сервер, а одного пользователя: 60 проверок в минуту и
2000 в сутки на адрес. Ответы из кэша квоту не тратят.

Чего эти числа не покрывают: если t.me начнёт резать наш IP, упадёт только
этот ключ — остальные продукты на том же сервере не заметят, они наружу не
ходят.

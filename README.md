# Ключи

Маленькие умные функции. Каждый ключ — одна папка. Из неё сами собой получаются
три вещи, ни одну из которых не пишут руками:

- **HTTP-эндпоинт** — `GET /k/alive?link=@durov`, зовётся из любого кода;
- **инструмент MCP** — один адрес в настройках, и все ключи появляются внутри
  ассистента (Claude, Cursor, IDE) как обычные команды;
- **страница документации** — генерируется из манифеста.

## Запуск

```
pip install -r requirements.txt
python run.py            # http://127.0.0.1:8110
pytest tests/ -q
```

## Как добавить ключ

Положить папку в `keys/`. Больше нигде ничего регистрировать не нужно — реестр
находит ключ сам по наличию `key.json`.

```
keys/
  мой-ключ/
    key.json      # что делает, что принимает, что возвращает, сколько кэшировать
    handler.py    # async def run(params: dict, ctx) -> dict
```

`ctx` — единственная дверь наружу: `await ctx.fetch(url)` уже проходит через
общий кран запросов и не даст ключу расстрелять наш IP.

Правила, которые проверяет загрузчик (кривой ключ до каталога не доедет):
`id` совпадает с именем папки, у каждого параметра есть тип из списка,
есть `summary` — короткая строка, которую читает и человек, и ассистент.

## Сколько выдержит сервер

Замеры на боевой машине (2 ядра, 3.8 ГБ, OVH Франция, 12 контейнеров уже
крутятся, load average 0.21):

| Что мерили | Результат |
| --- | --- |
| Одна страница t.me | ~10 КБ, **75 мс** |
| Восемь параллельно | **171 мс** на всю пачку (~47 проверок/сек) |
| Разбор страницы | **0.085 мс** → ~11 700 страниц/сек на одном ядре |

Вывод: процессор и память не при чём — разбор в 900 раз дешевле сетевого
похода. Узкое место одно — **терпение t.me к нашему IP**, а его в цифрах никто
не публикует. Поэтому наружу ходим через общий кран на **5 запросов/сек**
(в 9 раз ниже того, что тянет железо) = **432 000 проверок в сутки**.

Кэш этот бюджет умножает: живой канал держим 6 часов, мёртвый — 1 час, потому
что мёртвый может воскреснуть, а живой вряд ли исчезнет. При типичном для
каталогов перекрытии запросов (70% попаданий) сутки дают около **1,4 млн**
ответов.

Отсюда потолок по людям:

| Кто | Проверок в сутки | Сколько таких поместится |
| --- | --- | --- |
| Выжимает квоту досуха | 2000 | **~200** |
| Собирает каталог | ~300 | ~1400 |
| Обычный через ассистента | ~30 | **~14 000** |

Ограничивать надо не сервер, а одного пользователя: 60 проверок в минуту и
2000 в сутки на адрес. Ответы из кэша квоту не тратят.

Чего эти числа не покрывают: если t.me начнёт резать наш IP, упадёт только
этот ключ — остальные продукты на том же сервере не заметят, они наружу не
ходят.
